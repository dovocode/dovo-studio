# T3 Code review, 21 November 2026

Dovo should borrow T3's ACP test cases first. The useful cases cover temporary discovery failures,
late session configuration and model-specific options. After ACP, typed automation results offer the
clearest new feature. They address routines that pass one agent's answer to another step.

## Features worth testing in Dovo

1. **Typed routine results.** T3 stores a schema with the turn and gives the agent a tool to submit
   a validated result. Dovo already passes text and attachments through automation steps. A small
   first version could add a typed result for a routine that needs a downstream decision. Store the
   result with the exact step attempt. Keep the text and files available for review.
   [T3 typed results](https://github.com/pingdotgg/t3code/pull/38874) ·
   [Dovo step results](../packages/runtime/src/jobs/run-state.ts)
2. **Linked thread history across reconnect.** T3 preserves already loaded pages when a user reopens
   the same linked snapshot and filters out rolled-back runs when an older page arrives. Test Dovo's
   remote thread, cached history and rollback together using two paired runtimes.
   [T3 history fix](https://github.com/pingdotgg/t3code/pull/40545)
3. **Multi-repository review.** T3 added project-level repositories, per-thread Git targets and
   checkpoint coverage across repositories. Dovo already has linked checkouts with explicit access.
   Use T3's tests as a guide for selecting the right repository in review, staging and commit. Keep
   each checkout's permissions and ownership explicit.
   [T3 multi-repository project](https://github.com/pingdotgg/t3code/pull/35925) ·
   [Dovo linked checkout contract](../packages/protocol/src/workspace.ts)
4. **Agent MCP sign-in.** T3 opens the correct sign-in flow from the warning that an agent's MCP
   server needs authentication. Dovo can apply the same interaction when it can identify the exact
   server, agent and computer from the warning.
   [T3 sign-in](https://github.com/pingdotgg/t3code/pull/39921)
5. **Mobile controls and clipboard.** T3 increased tap targets in the model picker and terminal,
   added a local hit-box audit, and gave Android terminals an explicit close action. Its later
   attachment fix checks Display P3 through the downscale path. Check Dovo's real controls on iOS
   and Android. Check image colors in the submitted attachment as well as the preview.
   [Tap targets](https://github.com/pingdotgg/t3code/pull/40002) ·
   [Audit CLI](https://github.com/pingdotgg/t3code/pull/40102) ·
   [Terminal close](https://github.com/pingdotgg/t3code/pull/37640) ·
   [Image colors](https://github.com/pingdotgg/t3code/pull/40501)
6. **Git work driven by the current view.** T3 reuses tracked results when a complete Changes
   preview arrives, avoids repeating upstream reads, and retains branch results while refs are
   unchanged. Count Dovo's Git processes during a normal review before changing the cache. Include
   symbolic HEAD, remote changes, untracked files and a staging change during a scan.
   [Changes](https://github.com/pingdotgg/t3code/pull/40211) ·
   [Upstream](https://github.com/pingdotgg/t3code/pull/40450) ·
   [Branches](https://github.com/pingdotgg/t3code/pull/40452)

## Antigravity ACP and CLIProxyAPI

This follow-up checks
[T3 main at 404dd5ba](https://github.com/pingdotgg/t3code/commit/404dd5bad26dad5c1ea43e1949cab4d64e5c6822).

T3 checks the executable without starting ACP for each health poll. Its background catalog refresh
uses a disposable session. It visits the models in that session to collect their reasoning choices,
then removes the probe's session files. It also keeps a separate CLI profile and Google sign-in for
each configured account. This isolates account settings and leaves a user's terminal or IDE login
alone. Live conversations prefer `session/resume` to avoid replayed tool calls. T3 recommends
Antigravity 1.5.12 or newer.
[Driver](https://github.com/pingdotgg/t3code/blob/404dd5bad26dad5c1ea43e1949cab4d64e5c6822/apps/server/src/provider/Drivers/AntigravityDriver.ts)
·
[Setup](https://github.com/pingdotgg/t3code/blob/404dd5bad26dad5c1ea43e1949cab4d64e5c6822/docs/user/providers-antigravity.md)

Dovo already checks executable readiness without starting ACP and shares cached catalog results. It
now also keeps the same idle ACP v1 process for a supported Antigravity model change. Process
launch, resume and model selection took a median 425 ms on Linux with `agy` 1.5.14. The median for
an in-session model change was 11 ms across three samples. This measures ACP setup on one computer.
The direct CLI timed out on two available Gemini models, so live reply latency remains open.
[Dovo verification](./agent-providers.md#acp-v2-rollout)

T3 uses the CLIProxyAPI management key to list auth files and ask the hub to read each account's
usage. It supports Codex, Claude, Grok and Antigravity. The account model lookup runs separately
with a two-second timeout so it cannot hold up the quota reads. T3 can also redeem Codex reset
credits from the hub. Dovo already supports the management side for Codex and Claude with bounded
refresh work and per-account failure handling.
[T3 management client](https://github.com/pingdotgg/t3code/blob/404dd5bad26dad5c1ea43e1949cab4d64e5c6822/apps/server/src/usage/cliproxyApi.ts)
· [Dovo usage hubs](./usage.md#limits)

T3 configures the provider's inference endpoint separately from the usage hub. When they match, it
uses that hub's account and model limits for the thread. It also looks for the gateway's own
cooldown in provider errors when the proxy omits a structured quota snapshot. Dovo's hub
configuration currently supplies usage readings. The first parity change I would make is to show the
matching hub's limits in threads already configured to use that endpoint. Keep the management key on
the runtime and keep account or model availability unknown when the hub has no fresh data.
[T3 usage setup](https://github.com/pingdotgg/t3code/blob/404dd5bad26dad5c1ea43e1949cab4d64e5c6822/docs/user/usage.md#connect-a-cliproxyapi-hub)
·
[T3 retry fallback](https://github.com/pingdotgg/t3code/blob/404dd5bad26dad5c1ea43e1949cab4d64e5c6822/apps/server/src/usage/UsageLimitSources.ts)
