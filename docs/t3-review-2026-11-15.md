## Completed local adaptations

- [Native iOS image viewer](https://github.com/pingdotgg/t3code/commit/295a0a7332aa). The local Expo
  module pages through static image attachments. It supports zoom, swipe dismissal, sharing and Save
  to Files. It decodes the current page and its neighbors. GIF, Android and builds without the
  module keep the existing preview. Exports stay in private cache for up to a day so a share
  extension can read them. A failed download or decode can be retried. Layout keeps the Retry button
  visible. Retry fetches the bytes again and gives the decoder a new file URI. See the verification
  limits below.
- [Ranked folder search](https://github.com/pingdotgg/t3code/commit/752bdaeb708a). The runtime ranks
  exact, prefix, word boundary, substring and subsequence matches before paging. Both clients
  receive the same order. Existing hidden-folder rules remain.
- [Background OpenCode questions](https://github.com/pingdotgg/t3code/commit/03e05f6235cf) and
  [explicit dismissal](https://github.com/pingdotgg/t3code/commit/af8faa9cfa98). Child questions
  survive parent completion. Dismissal sends an explicit message. Reconnection checks both parent
  and active child sessions. SDK and local HTTP/SSE tests cover completion, dismissal, Stop and
  recovery. A live hosted OpenCode account was not used.
- [Prepare uploads before sending](https://github.com/pingdotgg/t3code/commit/f2c944947ddf). Clients
  check availability and renew pending uploads when the runtime advertises support. Desktop can
  restore bytes from a retained source file without changing the draft. It releases that source when
  the attachment leaves the composer. Missing mobile files give a recovery action. Draft changes
  during preparation stop the send. Runtime tests use real SQLite and HTTP. See
  [composer recovery](composer-recovery.md) for defaults and limits.
- [Keep history across provider switches](https://github.com/pingdotgg/t3code/commit/2e331341862b).
  The local Bot switching work checks OpenCode history transfer while excluding archived context.
  The picker includes available built-in and named ACP entries, including Pi and Antigravity.
  Unavailable entries stay hidden. This does not verify live Antigravity execution or every imported
  and remote-fork history path.

The earlier eight implemented additions remain documented in

background jobs, vault-reference checks, database space controls, folder drops, screen reader
