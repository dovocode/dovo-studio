# UI audit — 15 October 2026

Scope: spacing, alignment, overflow, responsive layout, typography, theme contrast and platform
navigation across the desktop/web shell, tasks/chat/review, SCM, settings, agents, runtime controls,
automation and native mobile source. Existing working-tree changes were preserved. UI findings below
are recommendations; this audit does not implement a visual redesign.

Evidence labels:

- **Browser reproduced:** actual components or the built desktop shell were inspected in managed
  Chromium. Fixture contexts and isolated runtime data do not represent all production states.
- **Source-backed:** a concrete constraint/caller mismatch exists in current source, but native
  geometry or the exact visual outcome has not been measured on a device.
- **Polish:** an intentional layout has a discoverability or consistency cost, rather than a broken
  interaction.

## Browser observations

At 390 pixels, the Issues and Automations header action strips show only part of their creation
button. The shared `.studio-page-actions` intentionally caps width at 65%, scrolls horizontally and
hides the scrollbar (`packages/studio-ui/src/styles.css:823`). These controls are scrollable, not
proven inaccessible. Treat this as **P3 polish/discoverability**, not a missing-action defect:
prioritize the primary creation action or move secondary actions into a visible overflow menu.

The PR tab strip also intentionally scrolls at narrow widths; off-viewport tabs alone are not a
finding. Header descriptions intentionally truncate. No arbitrary changes to the spacing scale or
these conventions are recommended without a demonstrated usability problem.

## Installed iOS startup crash follow-up

The first physical-device install exposed a startup failure missed by the browser fixtures and
successful bundle export: `Requiring unknown module "./impl/format"`. The shared code-theme parser
imports `jsonc-parser`; Metro selected its UMD entry, whose factory aliases `require`, leaving its
relative dependencies unresolved at runtime. The mobile Metro resolver now selects the package's
static ESM entry while retaining the default resolver for other packages.

`scripts/check-mobile-metro-modules.mjs` builds and executes a production iOS Metro bundle using the
actual Expo config. It reproduces the exact startup error with the original resolver and passes with
the fix. Mobile typechecking and scoped lint pass. The app was rebuilt, signed in the Mac Studio's
logged-in Terminal session, and installed over the existing app. A physical iPhone cold start stayed
running, and a screenshot confirmed the populated Tasks screen and saved computers. This verifies
startup on this device; it does not establish all the keyboard, diff and iPad scenarios above.
