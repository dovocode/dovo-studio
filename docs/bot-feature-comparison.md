# Bot feature comparison

Reviewed on 14 November 2026 against Dovo's current checkout, including its staged changes. Upstream
heads checked: T3 Code `eb14ddb7`, OpenBot `98cd89ec`, and Nod `e697ec36`. The tables retain the
original proposals. Implementation details, defaults and verification limits are in
[Bot reliability changes](upstream-bot-adoptions.md). An upstream fix does not establish the same
defect in Dovo.

## Recommended order

1. Add a computer-wide worker queue and repeated-tool-failure protection, then group routine
   notifications.
2. Add a small live-model evaluation suite to check unattended work.
3. Improve provider recovery and next-turn settings.
4. Extend monitoring and memory retrieval after those controls work.

| Stop repeated failed tool calls                   | Routine budgets and memory protection bound some resource use. The inspected execution and ACP paths did not establish an equivalent repeated-failure guard. | Detect consecutive calls with the same tool, arguments and error in one owned turn. ## Boundaries

Keep Dovo's interactive coordinator and worker model. Nod explicitly disables subagents in its
prompt, so its execution model is not a direct fit. Adopt useful behavior independently rather than
copying another product's architecture or licensed implementation.

Scheduled Bot worker threads stay outside normal thread overviews. Their transcripts and results
remain reachable through Bot work history. The prepared implementation is documented in
[Bot reliability changes](upstream-bot-adoptions.md); it is separate from the proposals above.

This review reads upstream source, release notes and local implementation. It does not verify
upstream runtime behavior, live-provider compatibility or physical phone audio.
